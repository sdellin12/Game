## Visual system

- Portrait artboard 750 x 1050, viewBox 0 0 750 1050 (5:7). This is a reference design
  canvas, not a promise of print bleed, CMYK, exact physical dimensions or printer
  compatibility. Rounded outer trim radius 36; foreground safe content starts 30–45
  units inside. Protect at least 20 units of important content from the trim.
- Ink/navy foundation #132 f 3 c, warm cream rules panel #f 7 f 1 df, restrained brass
  strokes and a color-specific accent. Color identity is also written explicitly.
- Georgia name text, Arial information text, system fonts. Gallery uses Segoe UI.
  No font files or remote font loading. PNG references were rasterized on Windows;
  other systems need equivalent installed fonts for pixel-identical typography.
- Name and card type at top left. Labeled play/summon/combine/access block at top
  right; ability activation costs remain inside the relevant ability panel.
- Traits lead the rules panel when present. Leader Reserve/Battlefield labels are
  explicit, not inferred from placement. Optional flavor can occupy otherwise
  unused ability space; no filler abilities are generated.
- Creature ATK bottom left and HP bottom right; labels and values are explicit.
  Non-creature cards omit those blocks. Zero ATK remains visible. Live HP may be 2/5.
- Brand/footer is optional decorative example material, not a required game field.
  The ILLUSTRATIVE CONTENT footer and artwork-placeholder badge identify examples;
  they can be disabled/restyled in a production renderer without removing rules.

### Standard treatment

Cream framed face. Rounded, clipped illustration window begins at y 166. Its bottom
moves up for denser rules. Rules occupy an opaque cream panel; stats/footer remain
on the cream face. The image is isolated from text and may be recropped.

### Full-art treatment

Illustration runs across the entire face inside the outer trim. A navy tint and
opaque header/rules panels preserve contrast. The same information positions and
rules-panel sizing are used; artwork remains visible behind/around the panels.
Full art does not mean removing rules, shrinking text or granting leader status.

## Shared content/slot contract

The JSON fixture object contains:

| Field | Meaning / template behavior |
|---|---|
| id | Safe lowercase slug for design filenames only. Not a production card ID. |
| name | Display name; renderer supports up to two 28-character title lines. |
| color | One of ten colors or Generic; palette in render.py. |
| type | Display type/role text. Persistent remains a provisional subtype label. |
| access_label, access | PLAY/SUMMON/COMBINE plus cost, or ACCESS plus FORM/TOKEN. Never fake a free play cost for a created entity. |
| access_detail | Optional public form/component/creation explanation in rules panel. |
| traits |0–2 display labels under the approved initial contract; sample vocabulary unregistered. |
| attack, health | Optional creature-only displayed stats; health can be a current/max string in a live fixture. |
| abilities | Ordered panels with optional label, cost, timing and required effect text. |
| flavor | Optional non-rules text used on an otherwise empty panel. |
| art, art_image | Human-readable illustration brief; optional local PNG/JPEG/WebP path inside design/cards/art for embedded artwork. |
| statuses, attachments, base_note | Optional example live-state overlays, not permanent definition edits. |
| note | Authoring note; not silently converted into gameplay text. |

Named SVG groups: `identity`, `access-cost`, `artwork`, `rules-panel`, `live-status`,
`stats`. Text is XML-escaped. Artwork lives in its own group and optional image
bytes are embedded as data URIs for standalone SVG use. External asset paths and
unsafe output IDs reject. No effect text is evaluated as code.

Design-fixtures-v1 is ONLY a design format. No existing saved game/catalog/report
schema changes. Future renderer integration must map an authorized card view model
into these slots and handle ownership/private projections correctly.

## Authored trigger wording / engine handoff
Practice pack v9 has three authored-trigger permanents.
Use the existing ordered `abilities` panels in both standard and full-art layouts:
- Scholar's Lantern: When you draw a card, you may gain 1 resource.
- Salvage Battery: When you discard a card from your hand, gain 1 resource.
- Archive Well (cost 5, ongoing capacity +1): When you discard a card from your
  hand, you may permanently add 1 resource capacity; available at the next refill.

Authoring also supports positive fixed healing rewards for the controller, but
no recurring-healing card is included in the practice pack. Keep life generation
cost decisions separate from the engine's supported instructions. Mixed rewards
are one effect and one Use/Skip decision. Permanent granted capacity survives the
source leaving play; its printed ongoing capacity bonus does not.
Archive Well's Use/Skip and next-Start behavior are verified across 54 directed
cases; strategy/cost evidence lives in experiments/DISCARD_STRATEGY.md. Printed
Battery/Well costs remain 4/5; experimental cost variants do not alter card files.

Preserve the actor, event, whether the reward is mandatory or optional, and printed
restrictions. Use "may" only for definitions marked optional. Do not shorten hand
discard into any discard entry. Use/Skip is a runtime choice, not a printed cost. Executable definitions live in crucible_core/cards.py and the practice pack;
`triggered_abilities` is not a new design-fixture field. Layouts and the shared
information contract are unchanged. Engine scope/evidence: experiments/TRIGGER_REWARDS.md.
Give another LLM this current document alongside an existing v1 layout ZIP; the
local ZIP may predate these wording notes. No generated design assets changed here.

## Capacity and live state

Body 23 units, metadata 20, traits 17, title 36 or 30 for two-line names, stats 34.
Text wraps by conservative character widths. Rule panel grows from 185 up to 470
units; art window adapts. Unbreakable overlong text, more than two title lines or
content exceeding panel capacity raises an error rather than silently clipping or
shrinking rules. These are v1 renderer limits, not new limits on game rules.
Extend/review the template or author equivalent shorter wording when necessary.
Do not delete costs, duration, targets or usage limits to get a green render.

Art direction stays cartoon-like and family-friendly: no realistic gore or
swearing. Theme/character flavor never silently changes a card's mechanics.

The live Pup fixture demonstrates base 2/3 -> current ATK 3/HP 2/5 plus exhaustion,
2 remaining prevention and Reinforced Plating. It does not change the base card's
abilities. A future renderer must supply controller/owner and all relevant live
statuses through authorized app state; these examples do not implement match UI.

## Historical v1 verification and remaining limits

At the published v1 checkpoint, all fifteen fixtures rendered into both variants. Five automated tests check text parity,
slot presence, conditional stats/real 0, safe paths, escaping, long names, overflow
rejection and checked-in output consistency. Locally rasterized basic, leader,
combined and live-state pairs were visually inspected; a low-contrast upgrade
label was fixed. Browser automation was unavailable because Firefox URL policy
enforcement is unsupported in the computer-use tool. No claim of cross-browser,
physical-print or all-device validation is made.

Both templates are v1 deliverables ready for independent design iteration. Final
character illustrations, production client integration, font licensing/embedding,
physical print setup and owner aesthetic refinements are separate from completion
of these editable information-preserving layouts. Example abilities/costs/traits
are untested candidate content, not approved starter cards.
