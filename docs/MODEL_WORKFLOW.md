# Model and Token Workflow
2026-11-22. Recommendations, not a claim that the main chat model can be switched automatically or that a particular model is offered in every user's picker.

- Routine coding, tests, CLI/desktop UI, docs, incremental bug fixes: use the normal capable coding model (Sol family; GPT-6.2 Sol when offered, otherwise current Sol option).
- Difficult rule ambiguity, simultaneous event/terminal ordering, architecture or statistical-method review: use the strongest reasoning option (Astra family; GPT-6.2 Astra when offered).
- Final independent audit: focused strongest-reasoning pass over the diff + test evidence, not the full interview.
- Bulk combat enumeration/matches/reporting: ordinary local code, no language model per game.
- Art: image model/backend, unrelated to choosing a premium coding model; no paid fallback.
If UI labels differ, ask which visible option corresponds rather than promise unavailable model names. Parent can recommend a model; supported subagent tools can select permitted model overrides when explicitly authorized, but parent cannot change its own running model.
Use moderate reasoning for routine work, deeper only on unresolved complex tasks. A more expensive model is not automatically more token-efficient. No exact usage or allowance guarantee.
